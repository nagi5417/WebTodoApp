# Comprehensive Code Review

## あなたの役割
指定されたファイル、または最近変更されたファイルに対して、6つの観点（コード品質、パフォーマンス、セキュリティ、エラーハンドリング、テスタビリティ、ベストプラクティス）から包括的なコードレビューを実施してください。

## 前提条件（CLAUDE.md参照）
- プロジェクト: WebToDoApp（タスク管理システム）
- フレームワーク: Spring Boot 2.7.18
- 既存コードスタイルに準拠すること
- **javax.validation** (※jakarta.validationではない)

---

## 実行手順

### ステップ1: レビュー対象の特定

**パターンA: ファイルパス指定あり**
- ユーザーが指定したファイルをレビュー対象とする

**パターンB: ファイルパス指定なし（自動検出）**
1. **Bashツール**で最近変更されたファイルを取得:
   ```bash
   git diff --name-only HEAD~5..HEAD
   ```
2. **Globツール**で主要なビジネスロジックを検索:
   - `**/*Service*.java`
   - `**/*Controller*.java`
   - `**/SecurityConfig.java`
3. ユーザーにレビュー対象を確認

---

### ステップ2: 対象ファイルの読み込み

**Readツール**で以下を読み込み:
1. レビュー対象ファイル
2. 依存しているクラス（必要に応じて）

---

### ステップ3: 6つの観点からレビュー

#### **観点1: コード品質 (Code Quality)**
- 命名規則の遵守
- マジックナンバー排除
- 単一責任原則（SRP）
- DRY原則
- メソッドの長さ（推奨50行以内）
- 循環的複雑度

#### **観点2: パフォーマンス (Performance)**
- **N+1問題**の有無
- 不要なデータベースクエリ
- ストリーム処理の適切性
- 大量データのバッチ処理

#### **観点3: セキュリティ (Security)**
- SQLインジェクション対策
- XSS、CSRF対策
- Spring Securityの適切な使用
- 機密情報の管理（パスワード、APIキー）

#### **観点4: エラーハンドリング (Error Handling)**
- 例外処理の適切性
- カスタム例外の使用（{Entity}NotFoundException）
- ログ出力の適切性
- エラーメッセージの分かりやすさ

#### **観点5: テスタビリティ (Testability)**
- コンストラクタインジェクションの使用
- インターフェースによる抽象化
- モック可能な設計

#### **観点6: ベストプラクティス (Best Practices)**
- **@Transactional**の適切な配置
- **Optional<T>**の活用
- Stream API、ラムダ式の適切な使用
- 設計パターン（Repository, DTO, Builder等）

---

### ステップ4: 問題の分類とスコアリング

各観点について100点満点で評価:
- **90-100点**: 🟢 良好
- **70-89点**: 🟡 改善推奨
- **0-69点**: 🔴 要改善

問題を重要度で分類:
- **🔴 重大 (Must Fix)**: パフォーマンス、セキュリティ、バグに直結
- **🟡 推奨 (Should Fix)**: 保守性、可読性の向上
- **🟢 良好 (Good)**: 既にベストプラクティスに従っている

---

## 重要な注意事項

1. **具体的なコード例を示す**（問題箇所と修正案）
2. **行番号を明記**（file_path:line_number形式）
3. **修正理由を説明**（なぜその修正が必要か）
4. **優先順位を明確化**（影響度×重要度で判断）
5. **Spring Boot 2.7.18のベストプラクティスに準拠**
6. **javax.validation使用を前提**（jakarta.validationではない）
