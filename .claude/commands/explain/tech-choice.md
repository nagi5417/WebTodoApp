プロジェクトで採用されている技術の選定理由と根拠を解説します。

## 実行フロー

### 1. 自動で技術スタックを検出

以下を自動解析：
- `build.gradle` or `pom.xml` - 依存ライブラリ
- `application.yml` - フレームワーク設定
- `package.json` - フロントエンド技術 (あれば)
- `Dockerfile`, `docker-compose.yml` - インフラ技術

### 2. 解説内容

各技術について以下を解説：

#### 📊 技術一覧
- Spring Boot, PostgreSQL, Flyway, Lombok, Thymeleaf など

#### 🎯 選定理由
- なぜこの技術が選ばれたのか
- プロジェクト要件との適合性

#### ✅ メリット
- パフォーマンス、開発効率、保守性、コミュニティ

#### ⚠️ デメリット
- 学習コスト、制約事項、パフォーマンスの制限

#### 🆚 代替技術との比較
- Spring Data JPA vs Spring JDBC
- PostgreSQL vs MySQL
- Thymeleaf vs React

#### 💡 ベストプラクティス
- この技術の推奨される使い方
- アンチパターン (避けるべき使い方)

### 3. 出力フォーマット

技術ごとに以下の形式で解説：
- 採用理由
- メリット/デメリット
- 比較表
- ベストプラクティス
- 参考リンク

---

**Note**: このコマンドは自律的に `build.gradle` や設定ファイルを読み込み、使用されている技術の選定理由を解説します。特定の技術について詳しく知りたい場合は、コマンド実行後に指定してください。
